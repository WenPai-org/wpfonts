# WPFonts 1.3 audit and remediation

Status: Phase 0 (1.3.0) system-stack hardening prepared for merge. This change is not a production release, not a CDN client, and not a settings-page rewrite. WordPress Global Styles and uploaded fonts are not migrated or deleted.

The August 2026 candidate was a reference. Notes below match the tree after that review was adapted onto current `main` (1.2.0 plus the October 2026 fleet URI wire).

## Scope and functional inventory

WPFonts has one runtime feature: on `init`, it registers four local JSON Font Library collections (Chinese 15, English 15, Japanese 5, Korean 5). Each entry is a system `fontFamily` stack and one category. WordPress exposes them through the authenticated Font Collections REST controller and persists a selected family into Global Styles/theme.json. WPFonts itself has no settings UI, AJAX, REST writes, SQL, user input, uploads, font downloads, CSS output, cron jobs, activation migration, or uninstall deletion.

The only external dependency is the vendored Plugin Update Checker 5.3 metadata client pointed at `https://updates.weixiaoduo.com/wpfonts.json`. It loads only for wp-admin, WP-Cron, and WP-CLI. If that library file is absent, the loader returns without a fatal error. The inactive `lib/updatepulse-updater` licensing implementation was not referenced by the main file and is removed. Collection JSON, language files, and (in the git tree) the update-checker library are bundled locally.

Multisite behavior: version 1.2 declared `Network: true` despite having no network data or network-only behavior. Version 1.3 removes that header, so a site administrator can activate per site and a network administrator can still network-activate. Deactivation/uninstall removes only executable code; existing Global Styles and uploaded fonts remain WordPress-owned user data. There is no uninstall routine.

## What was kept from live main

The August candidate rewrote Plugin URI / Author URI and dropped the `Update URI` header. This phase does not:

- Plugin URI stays `https://wpcy.com/wpfonts`.
- Author URI stays `https://wpcy.com/`.
- Header `Update URI` stays `https://updates.wenpai.net`.
- Plugin Update Checker metadata stays `https://updates.weixiaoduo.com/wpfonts.json`.

`updates.wenpai.net` was stale at 1.1.0 with an empty download link on 2026-08-09, so switching the live metadata host now would break updates. The two hosts are different mechanisms and both stay as they are on `main`.

## Confirmed defects fixed

1. **Compatibility contract:** 1.2 silently did nothing before WordPress 6.5 while update metadata claimed older WordPress compatibility. Plugin and readme headers now require WordPress 6.5 and PHP 7.4.
2. **Global slug collisions:** Chinese and English both used `system-ui` and `humanist`. All 40 family slugs are now language-prefixed (`cn-`, `en-`, `jp-`, `kr-`). Japanese and Korean slugs that already ended in `-jp` or `-kr` drop that suffix first (`system-ui-jp` becomes `jp-system-ui`, `system-ui-kr` becomes `kr-system-ui`, and the same for `calligraphic-jp`, `monospace-jp`, `rounded-jp`, `handwriting-kr`, `monospace-kr`, `regional-kr`). Existing Global Styles are not deleted or rewritten.
3. **Front-end updater load:** the Plugin Update Checker tree is about 708 KB and was parsed on every request. It is limited to admin, cron, and CLI. Ordinary front-end requests load the registration code and local collection paths only.
4. **Dead licensing surface:** unused UpdatePulse code (about 124 KB, including license AJAX/storage templates) was never required. It is removed without touching user data or the active update host.
5. **Multisite restriction:** the unjustified network-only header is removed. Both per-site and network activation remain possible.
6. **Documentation:** README, `readme.txt`, and the playground blueprint describe system stacks. They no longer call this build a Windfonts CDN or web-font service. A later CDN client is mentioned as optional and not implemented. Collection checks and a WordPress runtime smoke test are included.

## Security and data-flow verdict

There is no request handler, nonce path, capability check, SQL, template output, HTML escaping point, user-controlled URL, or font-download endpoint in plugin-owned code. The collection files contain no `url()`, `@import`, remote preview, or `fontFace.src`. WordPress core sanitizes Font Collection data again when loading the local JSON.

The custom updater remains the material trust boundary: metadata and ZIP are TLS-delivered from `updates.weixiaoduo.com`, but the metadata does not publish a SHA-256 or signature. The 2026-08-09 package hash was `5309b2249a069c5a40282a2b936dc461a738bef9cb1c6bae7a828ee9d2dbcfdd`; a one-time hash is historical evidence, not an authenticated update design, and it is not the hash of this change. Do not treat this pull request as a release. A release still needs a FeiCode commit/tag, an immutable ZIP, a SHA-256, and signed or otherwise controlled metadata.

Repository Forgejo workflows `auto-label.yml` and `stale-cleanup.yml` still call missing `scripts/auto-label.py` and `scripts/stale-cleanup.py`. Their scheduled jobs are not valid release evidence. This change does not redesign organization-wide CI.

`scripts/build-candidate.py` remains the existing fleet zip scaffold. It now includes `collection/` plus the main plugin file, `index.php`, `license.txt`, and `readme.txt`. It still excludes Plugin Update Checker, tests, docs, and scripts. That exclusion is pre-existing scaffold policy, not a new release pipeline. The updater loader no-ops when the library file is missing so that zip cannot fatal in wp-admin.

`scripts/public-docs-gate.py` allowlists `docs/README.md` and this audit file. Other docs paths still fail the gate.

## Performance budget

WPFonts adds four in-memory registration records on `init`. WordPress lazy-loads the four JSON files when collection data is requested. The catalog is 40 entries and about 24 KB on disk. No front-end asset or font byte is enqueued.

## Product direction

### In 1.3

- Four system-stack collections and WordPress core Font Library integration.
- Privacy-first, zero-font-download default.
- WordPress-owned Global Styles persistence and non-destructive uninstall.
- Language-prefixed family slugs without a data migration.

### Not in this change

- Settings UI, API key, CDN `<link>` embed, uploads, or Windfonts/wenfeng API clients.
- `lib/wenpai-admin-ui/`, `.wenpai-app`, or `Wenpai_Admin_*`.
- Rewriting user Global Styles or uploaded fonts.
- A new update host or release pipeline.
- camelCase / full phpcs cleanup inside vendored Plugin Update Checker.

A Windfonts web-font / CDN client, if built, is a later phase and needs its own admin UI review. Local font hosting is still a separate opt-in problem (license metadata, allowlisted types, checksums, capability checks, and cleanup that never deletes user fonts automatically). It is not part of 1.3.

Names such as `Hanyi Senty Candy`, `Alibaba PuHuiTi`, `MiSans`, and `Adobe Heiti Std` remain inside fallback stacks. A name in a stack does not distribute that font. The UI copy must not imply that WPFonts supplies those files. Renaming stacks is left for a later pass.
